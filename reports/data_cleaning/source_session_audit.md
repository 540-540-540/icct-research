**为什么确定是两个 source session，而不是一次连续录像里的普通编号异常：**

1. 两个不同的帧时钟 offset（差恰好 1,020,000 ms），不是单一时间基线；

5. 出生/死亡结构（见 §2）显示两段各自有独立的“车辆出生流”，并在 8:45:00.0 处精确切换。

## 2. 约 100.6 s “重叠”到底是什么

- Session 0：08:28:00.2 – 08:46:40.6；Session 1：08:45:00.0 – 09:02:27.0
- 共同覆盖 `Global_Time`：**[1,118,936,700,000, 1,118,936,800,600]，100.6 s**
- 帧号关系：同一 `Global_Time` 下 **Session 1 帧号 = Session 0 帧号 − 10,200**

| 重叠区 | 行数 | 车辆数 | Frame_ID 范围 | 车辆/帧 演化 |
|---|---|---|---|---|
| Session 0 | 29,671 | 72 | 10,201 – 11,207 | 72 → … → 1（逐帧衰减） |
| Session 1 | 51,204 | 124 | 1 – 1,007 | 6 → … → 58（逐帧增长） |

**出生/死亡结构（决定性证据）**：按“每辆车首次出现时刻（birth）”统计：

| | Session 0 | Session 1 |
|---|---|---|
| 每分钟新增车辆（前 16 分钟） | 49–92 | 60–96 |
| 最后一分钟新增 | 第 17–18 分钟 = **0** | 第 15–17 分钟 = 1 / 0 / 0 |
| **最后一辆出生** | 1,118,936,699,900（= 08:44:59.9，边界前 0.1 s） | 1,118,937,600,000（= 09:00:00.0） |
| 出生时刻 ≥ Session 1 首帧的 Session 0 车辆 | **0** | — |
| 首帧（08:45:00.0）即存在的 Session 1 车辆 | — | 6 辆（ID 2,5,6,7,8,9） |
| `Vehicle_ID` 与出生时刻 Spearman 相关 | 0.972 | 0.976 |
| 每帧车辆数：首 12 帧 / 末 12 帧 | 2 / 1 | 6 / 1 |

结合 FHWA 文档，这两个 session 是**同一次连续 10 Hz 观测按车辆“出生时间”切分的两个官方时段文件**：

- Session 0 = 在 **8:45:00.0 之前**出生的车辆，导出其完整轨迹（因此死亡流延续到 8:46:40.6，超出时段名义结束 100.6 s）；
- Session 1 = 在 **8:45:00.0 – 9:00:00.0** 之间出生的车辆，导出其完整轨迹（死亡流延续到 9:02:27.0）；
- 于是“100.6 s 重叠”= **Session 0 的车流尾巴** 与 **Session 1 的车流头部** 在时钟上叠在一起，两者装的基本是**互补的两批车**，而不是同一场景的重复画面。

**逐帧场景证据（同一时刻两段内容不同、但物理上可拼成一个连续交通流）：**

- t = 1,118,936,740,000（重叠中段）：Session 0 在 Direction 4 有 25 辆**静止排队**（Local_Y 449–682 ft）；Session 1 的 Direction 4 在此刻是 Y 831–1,605 ft 的**运动车流**，且其 Y 679.8 处恰是队列尾。方向 2 的排队亦然：**队首在 Session 0（Y 297–342，边界前出生），队尾在 Session 1（Y 51–291，边界后出生）**，两段在 Y 291–342 处无缝衔接成一列完整队列。
- 若两段是“同一现实的同时刻完整记录”，交通状态（排队 vs 流动）与车辆分布不可能不同；若两段是无关录像，队列又不可能跨段连续对齐。⇒ 同一条连续车流，被出生时间切成两段导出。

**按任务选项的分类：C（两个录像存在部分真实连续/重复内容）**，更精确说：

- **不是 A**：重叠区没有“同一场景被记录两遍”——两段的车辆集合几乎不重叠（见 §3，99% 以上为互补内容）；
- **不是 B**：不是两次无关录像——同一连续时钟、同一条路、车辆队列跨段连续、并有少量车辆被同时跟踪；
- **是 C 的变体**：同一连续观测的两个“出生队列”导出窗口在时钟上重叠 100.6 s，其中**4 辆边界车被两段同时导出**（重复内容），其余为互补内容。

> 证据等级：STRONG EVIDENCE（互补队列与同源时钟）；导出规则细节 UNCERTAIN（见文末）。

## 3. 轨迹内容验证：重叠区是否真的重复

统一使用 `Global_X/Y × 0.3048`（米）做跨会话空间匹配。

### 3.1 同时刻匹配率（Session 1 重叠区 51,204 个点 vs Session 0 同时刻全部车辆）

| 半径 | 匹配点 | 占比 |
|---|---|---|
| ≤ 0.5 m | 838 | 1.6% |
| ≤ 1 m | 1,853 | 3.6% |
| ≤ 2 m | 1,995 | 3.9% |
| ≤ 3 m | 2,701 | 5.3% |
| ≤ 5 m | 4,216 | 8.2% |
| 安慰剂（同样本对 Session 0 的 t−10 s，≤2 m） | 1,876 | 3.7% |

同时刻匹配率与安慰剂无差别 ⇒ **重叠区绝大多数车辆在两段中不是同一批车**。

### 3.2 匹配到的轨迹对（≥5 帧且 ≤2 m）

| Session 1 ID | Session 0 ID | 匹配帧 | 中位误差 | 速度相关系数 | 同车道比例 | 判定 |
|---|---|---|---|---|---|---|
| 2 | 1418 | 941 | 0.56 m | 0.996 | 99.9% | **同一辆车** |
| 5 | 1421 | 894 | 0.25 m | 0.998 | 98.5% | **同一辆车** |
| 7 | 1422 | 114 | 0.36 m | 0.990 | 97.4% | **同一辆车** |
| 6 | 1420 | 34 | 0.90 m | 0.905 | 94.1% | **同一辆车** |
| 57 | 1410 | 7 | 1.46 m | 0.109 | 2.0% | 偶然匹配（相邻车道） |

- 这 4 辆车的共同帧覆盖整个 100.6 s 重叠区（如 S1 ID 2 帧 1–965，S0 ID 1418 帧 10,190–11,167），速度相关系数 0.99+，是**真实的重复轨迹**。
- 4 辆车（S1 ID 2/5/6/7）恰好是 Session 1 的首批 ID，对应 Session 0 的末批 ID（1418/1420/1421/1422）——这正是“时段边界被两段同时初始化”的签名。Session 1 首帧共 6 辆车，其中 2 辆（ID 8/9）只有 3 m 级、误差 ~2.5–3 m 的弱匹配，无法确认同一性。

### 3.3 固定时间偏移搜索

在 Session 1 全程抽样时间点上，按固定偏移 Δt 匹配 Session 0（≤2 m）：

| 偏移 Δt | 0 s | +510 s | +1,020 s | +1,530 s |
|---|---|---|---|---|
| 匹配率（≤2 m） | 3.98% | 16.8% | 14.7% | 11.9% |

四个偏移都是同一背景量级，**不存在使两段内容重合的固定时间偏移**（若 Session 1 是 Session 0 的重定时复制，+1,020 s 处应出现接近 100% 的匹配）。

### 3.4 场景分布对比

逐帧对 `Global_Y` 分位数（P10/25/50/75/90）取两段差值（越小越像同一场景）：

| 对比 | 同时刻 | 滞后 −60 s | −30 s | +30 s | +60 s |
|---|---|---|---|---|---|
| 平均差 | **118.9 m** | 76.7 m | 81.2 m | 117.1 m | 112.2 m |

同时刻并不比错位更接近 ⇒ 再次否定“同一场景重复记录”（该检验对互补队列本身不敏感，仅用于排除 A 类重复）。

> 结论：重叠区**不存在成片的真实重复轨迹**，只存在 **4 辆边界重复车**；其余内容为互补车流。证据等级：CONFIRMED（4 辆重复）/ STRONG EVIDENCE（无成片重复）。

## 5. 文件排序结构与时间异常归因

### 5.1 排序规则

文件 = `[Session 0 块][Session 1 块]`；每个 session 内**近似**按 `(Vehicle_ID, Frame_ID)` 升序，但并非严格：2,442 个键产生了 **2,458 个连续 run**（16 个键被拆成 2 段），且存在 **228 处负数时间步**。

### 5.2 异常归因：全部是行序错位，不是轨迹断裂

| 文件顺序统计（同一 `(session, Vehicle_ID)` 内相邻行） | 值 |
|---|---|
| 轨迹内相邻跳变总数 | 1,604,877 |
| 恰好 100 ms | 1,604,206 |
| 200 ms | 220 |
| (100, 1000) ms | 3 |
| ≥ 1000 ms（max +39,200 ms） | 220 |
| 负步（min −39,100 ms） | **228** |
| 负步后下一跳立即回到 100 ms 序列 | **227 / 228** |

关键核对：

- **重复行数 = 0**：`(session, Vehicle_ID, Frame_ID)` 重复 0 行，`(session, Vehicle_ID, Global_Time)` 重复 0 行 ⇒ 错位行都是“唯一行”，不是重复数据；
- **按 `Global_Time` 排序后**：全部 1,604,877 个间隔 **= 100 ms（0 个非 100 ms）**；2,442/2,442 条轨迹的“行数 = Frame_ID 跨度”，即**每条轨迹都是无缝隙的 10 Hz 连续段**。

典型错位实例：

- `(0, 81)`：帧 356 的行被插在帧 115 与 116 之间（帧集合本身是 106–824 连续 719 帧）；
- `(0, 140)`：帧 572 的单行被插进 `(0, 139)` 的块内，导致两个键各被拆成 2 个 run；
- `(0, 165/166)`、`(0, 267/269)`、`(0, 467/468)`、`(0, 1387/1388)`、`(1, 259/260)`、`(1, 926/928)`、`(1, 1130/1131)` 同型。

### 5.3 此前报告中的“负步 / 200 ms / ±39 s”到底是什么

- **228 个负步**：行序错位（错位行提前出现）产生，**不是**车辆真实轨迹断裂；
- **220 个 200 ms 与 220 个 ≥1 s 正向跳变**：同一批错位行的镜像（插入时 +大跳，归位时 −大跳），**不是**采样缺失；
- **真实轨迹断裂 = 0**：排序后无任何非 100 ms 间隔。

> 证据等级：CONFIRMED（排序后 0 非 100 ms、0 重复行、2,442/2,442 连续）。

## 6. 对后续正式清洗的直接提示（本轮未执行）

5. 2005-06-16 时钟换算（PDT）：session 边界 1,118,936,700,000 ms = 08:45:00.0，与 FHWA “8:30–8:45 / 8:45–9:00” 两时段文档一致。
