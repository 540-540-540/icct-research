## 5. 结果摘要中各类文件的职能

同一实验的文件通常共享前缀，例如 `effective_segment_qgnn_llm_seed2026_v1`；后缀区分文件用途。下列说明以现有有效关系接口记录为例，具体字段以文件内容为准。

| 文件类别 | 职能 | 使用方式 |
|---|---|---|
| `__protocol.json` | 实验协议 | 先核对种子、模型分支、选择/确认场景和 `no_test` 标记 |
| `__summary.json` | 指标与评估结果 | 查模型选择、确认和全开发集等不同字段，区分所属集合 |
| `__smoke.json` | 小规模数值/梯度等检查 | 查看接口实现检查；它不提供完整性能结论 |
| `__completed.json` | 运行完成状态及随附结果快照 | 查看该次运行状态；不是独立重复实验 |
| `__contribution_chain.json` | 贡献链与对照统计 | 比较组件增益、经典对照和相关统计区间 |
| 消融、困难场景、复杂度分层 JSON | 针对特定问题的分析 | 结合对应模型版本、子组和协议解释 |
| `intent_token_oracle_seed2026_v1.json` | 使用未来标签的诊断 | 文件明确标记诊断用途，不能作为可部署预测结果 |

此处 12 份 `__summary.json` 均标记 `no_test=true`。早期测试结果另见研究原始记录和云端快照，不能把摘要目录当作全部实验产物。**查指标时按“协议 → 摘要 → 源记录/原始产物”阅读。**

## 7. 副本、摘要、快照与恢复包是什么关系

这些目录来自同一批历史材料，分别承担检索、追溯和恢复职责：

| 从哪里开始 | 需要更多上下文时到哪里 |
|---|---|
| `02_代码阅读副本/`：按阶段找脚本 | `04_云端完整快照/`：找原位置代码、共享依赖、检查点和实验输出 |
| `03_结果摘要/`：集中查结构化结果 | `01_研究文档/原始记录/` 与 `04_云端完整快照/`：核对解释、实验上下文和原始产物 |
| `04_云端完整快照/`：直接访问已展开材料 | `05_Linux恢复包/`：恢复未展开的特定修订内容，或查根文件保险副本 |
| `06_环境记录/`：了解原运行环境 | `07_归档核验资料/`：了解原下载、采集和核验过程 |

完整快照指本地已归档展开子树完整保留，并不表示整个服务器被完整复制。Linux 虚拟环境未复制；`revision_unified_20260907`、`revision_r1c1_20260907` 以恢复包提供。根文件包与展开快照存在有意重复，恢复包也不替代整个工程。

`02_代码阅读副本/` 的公共与经典脚本主要对应快照根目录；QGNN 核心主要对应 `diagnostics/core_message_seed2026_v2/`；后期接口和量子关联还对应“未来词实验”和“量子关联图验证”原目录。本次依据归档说明及路径定位这些关系，没有重新逐字节比较副本。

历史源文件内容保留，旧路径按下表换算；需要查某个具体文件时，搜索[原有文件清单](原有文件清单.json)中的 `OriginalPath`，读取对应 `CurrentPath`。

| `docs/source_archives/` | `01_研究文档/原始记录/` |
| `code/` | `02_代码阅读副本/` |
