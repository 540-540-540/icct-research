# 第二图：不确定性感知的量测—航迹关联图完整流程方案

> 当前状态：方案设计阶段  
> 本文件只定义研究问题、输入输出、模型结构、训练流程和实验验证方案；暂不包含代码、实验结果或可视化。

## 1. 研究定位

已完成的目标—目标交互图建立在“每段历史轨迹属于哪辆车已经知道”的前提上，因此解决的是多目标之间如何相互影响以及未来如何运动，而不是多目标跟踪中的身份判别。

第二图需要解决的问题是：

> 在多基站 ISAC 每帧产生数量可变、顺序无关且不带车辆身份的量测集合时，如何判断每个量测属于哪条已有航迹，同时处理漏检、虚警、新生目标和航迹消失，并将关联不确定性传给后续目标交互图与 LLM 预测器。

完成第二图后，完整系统才能从“已知身份的多目标预测”扩展为“未知身份量测下的多目标跟踪与预测”。

## 2. 双图系统中的位置

```text
多 BS 多目标回波
        ↓
RD/RA 峰值检测与量测候选提取
        ↓
多 BS 量测融合与协方差估计
        ↓
第二图：量测—航迹关联图
        ↓
航迹状态、身份、协方差和关联熵更新
        ↓
第一图：目标—目标交互图
        ↓
不确定性引导的运动 Token
        ↓
GPT-2/LoRA 多目标未来轨迹预测
```

虽然第二图在开发顺序上晚于第一图，但在实际推理时间顺序上位于第一图之前。

## 3. 推荐研究范围

### 3.1 论文主体采用的可实现版本

建议先采用“多 BS 融合量测 + 航迹二部图”的分层方案：

1. 每个 BS 独立执行峰值检测，获得距离、Doppler、角度和幅度量测；
2. 根据多 BS 几何一致性，将不同 BS 的量测融合为空间候选点；
3. 将融合候选点作为量测节点，将已有航迹预测状态作为航迹节点；
4. 构建量测—航迹二部图并输出软关联概率；
5. 通过一一匹配和航迹生命周期管理得到最终离散关联结果；
6. 用关联概率加权更新状态，并计算关联熵。

该版本职责清晰，容易与 Hungarian、JPDA 等传统方法公平比较，也能在硕士论文时间范围内完成。

### 3.2 后续可选扩展

若主体版本完成后仍有时间，可把各 BS 原始量测直接作为异构图节点，同时学习跨 BS 量测融合和量测—航迹关联。但这会引入多维匹配和更复杂的监督，不建议作为第一版唯一方案。

## 4. 数据输入设计

### 4.1 无身份量测集合

在时刻 \(t\)，模型接收无序量测集合：

\[
\mathcal Z_t=\{\mathbf z_{1,t},\ldots,\mathbf z_{N_t,t}\},
\]

其中 \(N_t\) 会随着目标数量、漏检和虚警发生变化。每个融合量测节点建议包含：

\[
\mathbf z_{j,t}=
[x,y,v_x,v_y,\mathrm{SNR},s_{\mathrm{det}},n_{\mathrm{BS}},
\operatorname{diag}(\mathbf R),\log|\mathbf R|,\mathbf m_{\mathrm{BS}}],
\]

其中：

- \((x,y,v_x,v_y)\)：多 BS 融合后的位置和速度估计；
- `SNR`：量测信噪比或多 BS 聚合信噪比；
- \(s_{\mathrm{det}}\)：检测置信度；
- \(n_{\mathrm{BS}}\)：参与该候选量测融合的基站数量；
- \(\mathbf R\)：量测协方差；
- \(\mathbf m_{\mathrm{BS}}\)：基站可见性掩码。

量测输入中不得包含车辆真实 ID。真实 `Vehicle_ID` 只能用于构造训练标签和测试评估。

### 4.2 航迹先验集合

上一时刻维护的航迹集合为：

\[
\mathcal T_{t}^{-}=\{\tau^-_{1,t},\ldots,\tau^-_{M_t,t}\}.
\]

每个航迹节点建议包含：

\[
\tau^-_{i,t}=[\hat x,\hat y,\hat v_x,\hat v_y,
\hat a_x,\hat a_y,\psi,
\operatorname{diag}(\mathbf P^-),\log|\mathbf P^-|,
a_i,m_i,c_i,\mathbf h_i],
\]

其中：

- \(\mathbf P^-\)：预测状态协方差；
- \(a_i\)：航迹年龄；
- \(m_i\)：连续漏检次数；
- \(c_i\)：航迹置信度；
- \(\mathbf h_i\)：历史运动或上一帧图状态编码。

### 4.3 推荐张量接口

```text
track_features:       [B, M_max, D_track]
measurement_features: [B, K_max, D_measurement]
edge_features:        [B, M_max, K_max, D_edge]
track_mask:           [B, M_max]
measurement_mask:     [B, K_max]
association_gt:       [B, M_max + 1, K_max + 1]
```

额外的一行和一列用于表达未匹配、漏检、虚警和新生目标。

## 5. 多目标量测生成流程

### 5.1 保留共同时间轴和真实相对位置

从 NGSIM/Lankershim 原始数据按 `Global_Time` 和空间 ROI 构造多车辆场景。不得再逐车重置时间原点或分别随机平移，否则会破坏车辆之间的真实交互和身份关系。

### 5.2 多目标回波叠加

对每个 BS 和每一帧，应按目标逐项生成二维雷达原子后求和：

\[
\mathbf Y^{\mathrm{RD}}_{b,t}=
\sum_{q=1}^{Q_t}\alpha_{b,q,t}
\mathbf a_r(r_{b,q,t})\mathbf a_v(v_{r,b,q,t})^{H}
+\mathbf C_{b,t}+\mathbf N_{b,t},
\]

\[
\mathbf Y^{\mathrm{RA}}_{b,t}=
\sum_{q=1}^{Q_t}\alpha_{b,q,t}
\mathbf a_r(r_{b,q,t})\mathbf a_\theta(\theta_{b,q,t})^{H}
+\mathbf C'_{b,t}+\mathbf N'_{b,t}.
\]

不能先分别把所有一维距离、速度或角度响应相加后再做一次外积，否则会产生不属于任何真实目标的交叉项。

### 5.3 峰值检测和异常量测

每个 BS 独立执行 CFAR 或局部峰值检测，并显式控制：

- 检测概率和漏检率；
- 每帧虚警数量或虚警密度；
- RCS/幅度波动；
- 静态杂波；
- SNR；
- BS 暂时失效或可见性变化。

### 5.4 多 BS 量测融合

主体版本建议先采用物理几何驱动的融合方法：

1. 根据 range/angle 几何门控构造跨 BS 候选组合；
2. 使用 Doppler 和时间一致性去除不合理组合；
3. 采用协方差加权最小二乘或后验融合得到空间位置、速度和协方差；
4. 未能被多个 BS 支持的单站候选保留较低置信度，而不是直接删除；
5. 输出数量可变、无身份的融合量测集合。

这样能把“跨 BS 物理融合”和“跨帧身份关联”分开，便于定位误差来源。

## 6. 量测—航迹二部图构建

### 6.1 节点类型

图中包含两类节点：

- 航迹节点 \(v_i^{T}\)：表示已有航迹在当前帧到来前的预测状态；
- 量测节点 \(v_j^{Z}\)：表示当前帧的一个无身份融合量测。

### 6.2 候选边和物理门控

不是所有航迹与所有量测都连接。对每个候选对 \((i,j)\)，首先计算创新：

\[
\boldsymbol\nu_{ij}=\mathbf z_j-\mathbf H\hat{\mathbf x}^{-}_i,
\]

以及马氏距离：

\[
d^2_{ij}=\boldsymbol\nu_{ij}^{T}
(\mathbf H\mathbf P_i^{-}\mathbf H^T+\mathbf R_j)^{-1}
\boldsymbol\nu_{ij}.
\]

仅保留通过卡方门限的候选边，并为每条边构造：

```text
[位置创新、速度创新、马氏距离、欧氏距离、
 径向速度残差、航向差、时间间隔、
 量测 SNR、检测置信度、BS 支持数量、
 航迹协方差、量测协方差、可见性一致性]
```

门控既减少计算量，也避免 GNN 被大量明显不可能的负边淹没。对极端拥挤场景，可在门控后再为每条航迹保留距离最小的 top-k 个量测。

### 6.3 为什么不能只用欧氏距离

轨迹交叉时，两个目标的位置可能非常接近，但速度方向、Doppler、历史状态协方差和 BS 可见性不同。只用欧氏距离容易在交叉点产生 ID Switch；马氏距离和多模态残差可以显式利用感知不确定性与运动连续性。

## 7. 关联 GNN 模型结构

### 7.1 节点编码

使用独立的 MLP 对航迹节点和量测节点编码到统一维度：

\[
\mathbf h_i^{T,0}=f_T(\tau_i^-),\qquad
\mathbf h_j^{Z,0}=f_Z(\mathbf z_j).
\]

### 7.2 二部消息传递

建议使用 2～3 层带边特征的 GATv2 或 Graph Transformer，交替执行：

1. 量测节点向航迹节点传递候选观测证据；
2. 航迹节点向量测节点传递运动先验和身份上下文；
3. 更新候选边表示，使其同时包含局部残差和邻域竞争关系。

邻域竞争非常重要：一个量测是否属于航迹 \(i\)，不仅取决于二者是否相似，还取决于该量测是否更适合另一条航迹。

### 7.3 边评分头

对每条候选边输出关联 logit：

\[
s_{ij}=f_e([\mathbf h_i^T,\mathbf h_j^Z,\mathbf e_{ij}]).
\]

同时为每条航迹输出漏检 logit，为每个量测输出虚警/新生 logit。最终得到扩展关联矩阵：

\[
\mathbf S_t\in\mathbb R^{(M_t+1)\times(N_t+1)}.
\]

### 7.4 软匹配与离散匹配

训练阶段建议使用带 dustbin 的 Sinkhorn 或 unbalanced optimal transport，将边分数转换为近似双随机的软关联概率：

\[
\mathbf A_t=\operatorname{Sinkhorn}(\mathbf S_t/\tau_a).
\]

推理阶段采用两层输出：

1. 保留 \(\mathbf A_t\) 作为关联不确定性的概率表示；
2. 对有效关联代价执行 Hungarian，得到满足一一约束的离散匹配。

这样既能保持跟踪输出的确定性，又不会丢失关联熵。

## 8. 状态更新与关联不确定性

### 8.1 软关联量测

对航迹 \(i\)，使用关联概率构造加权量测：

\[
\bar{\mathbf z}_{i,t}=\frac{\sum_j A_{ij,t}\mathbf z_{j,t}}
{\sum_j A_{ij,t}+\epsilon}.
\]

可采用可微 Kalman 更新或门控 GRU 状态更新。第一版优先使用显式 Kalman 更新，因为物理意义清晰，便于与传统跟踪器公平比较。

### 8.2 关联熵

对每条航迹计算归一化关联熵：

\[
H^{\mathrm{assoc}}_{i,t}=
-\frac{1}{\log(N_t+1)}
\sum_{j=0}^{N_t} A_{ij,t}\log(A_{ij,t}+\epsilon).
\]

低熵表示某一量测归属明确，高熵表示多个候选量测难以区分。状态协方差更新时应随关联熵增大而膨胀，避免模型在身份不确定时仍给出过度自信的状态。

### 8.3 与第一图和运动 Token 的连接

第二图向第一图输出：

```text
updated_state:        [B, M_max, D_state]
updated_covariance:   [B, M_max, D_cov]
track_confidence:     [B, M_max]
association_entropy:  [B, M_max]
track_mask:           [B, M_max]
track_identity:       内部维护的匿名航迹编号
```

第一图的目标节点特征增加 `association_entropy` 和 `track_confidence`。运动 Token 温度扩展为：

\[
T_{i,t}=\operatorname{clip}\left(
T_{\mathrm{base}}
+\alpha\bar u_{i,t}^{\gamma}
+\beta H^{\mathrm{assoc}}_{i,t},
T_{\min},T_{\max}
\right),
\]

其中 \(\bar u_{i,t}\) 表示定位/状态不确定度，\(H^{\mathrm{assoc}}_{i,t}\) 表示身份关联不确定度。这是第二图与第一篇“不确定性引导运动 Token”之间最关键的理论连接。

## 9. 航迹生命周期管理

每条航迹具有四种状态：

```text
Tentative → Confirmed → Lost → Deleted
```

推荐规则：

1. 未匹配量测连续出现若干帧后创建新航迹，避免把单帧虚警直接当作新目标；
2. 已确认航迹短时漏检时依靠运动模型继续预测，并增加协方差和 `miss_count`；
3. 在允许的最大失配帧数内重新匹配成功，则恢复为 Confirmed；
4. 长时间未匹配则删除；
5. 航迹内部使用系统分配的匿名 track ID，真实车辆 ID 只用于离线监督和评估。

具体确认帧数和删除阈值应在验证集上选择，不应根据测试集调参。

## 10. 监督标签构造

仿真数据生成阶段保留量测来源的真实 `Vehicle_ID`，但只在离线构造标签时使用：

\[
y_{ij,t}=1
\quad\Leftrightarrow\quad
\text{measurement }j\text{ and track }i
\text{ originate from the same vehicle}.
\]

此外需要标注：

- 已有航迹在当前帧是否漏检；
- 每个量测是真实目标、虚警还是新生目标；
- 目标出生和离开时间；
- 每个 GT 目标对应的连续身份序列。

训练、验证和测试必须按不重叠的连续时间段或完整场景划分，禁止同一车辆相邻窗口跨集合造成身份或运动泄漏。

## 11. 损失函数

建议采用：

\[
\mathcal L_{\mathrm{assoc}}=
\lambda_{e}\mathcal L_{\mathrm{edge}}
+\lambda_{ot}\mathcal L_{\mathrm{OT}}
+\lambda_{miss}\mathcal L_{\mathrm{miss/birth}}
+\lambda_{state}\mathcal L_{\mathrm{state}}
+\lambda_{id}\mathcal L_{\mathrm{identity}}
+\lambda_{cal}\mathcal L_{\mathrm{calibration}}.
\]

各项含义如下：

- \(\mathcal L_{\mathrm{edge}}\)：候选边关联分类，可使用带类别权重的 BCE 或 focal loss；
- \(\mathcal L_{\mathrm{OT}}\)：软匹配矩阵与真实匹配矩阵的交叉熵或 KL；
- \(\mathcal L_{\mathrm{miss/birth}}\)：漏检、虚警和新生目标分类；
- \(\mathcal L_{\mathrm{state}}\)：更新状态的 Gaussian NLL 或位置/速度 Smooth-L1；
- \(\mathcal L_{\mathrm{identity}}\)：同一目标跨帧嵌入拉近、不同目标推远的对比损失；
- \(\mathcal L_{\mathrm{calibration}}\)：约束关联概率与实际正确率一致，避免过度自信。

候选负边数量远大于正边，必须使用物理门控、困难负样本挖掘或类别重加权，不能直接对全部负边做等权训练。

## 12. 分阶段训练流程

### 阶段 A：量测生成与传统跟踪器验证

1. 生成无身份量测、漏检、虚警和 GT 关联标签；
2. 检查量测数量、误差分布和协方差覆盖率；
3. 实现 CV/CA-KF + 最近邻、gated Hungarian-EKF 和 JPDA-EKF；
4. 确认传统基线能够在简单场景维持身份。

若传统基线完全无法工作，优先检查量测仿真和门控，而不是直接训练 GNN。

### 阶段 B：单帧关联图预训练

1. 使用 GT 航迹先验或加入可控噪声的预测状态；
2. 训练节点编码、二部消息传递和边评分；
3. 只评价边分类、匹配准确率、漏检和虚警识别；
4. 确认 GNN 优于仅使用马氏距离的匹配网络。

### 阶段 C：序列跟踪训练

1. 将模型输出的航迹状态递归输入下一帧；
2. 从 teacher forcing 逐步过渡到模型自身状态；
3. 加入出生、消失、连续漏检和交叉场景；
4. 用 HOTA、IDF1 和 ID Switch 选择最佳检查点。

### 阶段 D：连接已完成的目标交互图

1. 先冻结关联图，使用其输出替代 oracle 历史身份和状态；
2. 评估预测关联相对 oracle 关联造成的 ADE/FDE 差距；
3. 将关联熵输入运动 Token 温度；
4. 验证加入关联熵是否改善交叉、遮挡和低 SNR 场景；
5. 最后以较小学习率进行有限联合微调，避免跟踪和预测损失互相干扰。

## 13. 实验难度课程

建议按以下顺序递增难度：

1. 2～4 个目标，无漏检、无虚警；
2. 4～8 个目标，加入 5/10/15/20 dB 量测噪声；
3. 加入 5%、10%、20% 漏检率；
4. 加入不同虚警密度；
5. 加入轨迹交叉、并线、转弯和短时遮挡；
6. 加入单 BS dropout 和部分基站可见；
7. 测试不同目标数量和未见密度的泛化能力。

每一阶段必须固定测试场景和随机噪声种子，保证各关联方法面对完全相同的量测集合。

## 14. 对比方法

### 14.1 传统跟踪与关联基线

- CV-KF + Nearest Neighbor；
- gated Hungarian + EKF；
- JPDA-EKF；
- 可选：MHT 或简化 Track-Oriented MHT；
- Oracle association，作为身份已知的性能上限。

### 14.2 学习关联基线

- 仅边 MLP，不进行图消息传递；
- 相同二部图 GNN，但不输入协方差和 SNR；
- 相同 GNN + Hungarian，不使用软匹配/关联熵；
- 若数据接口允许，再选择公开的图匹配或雷达多目标跟踪模型作为外部强基线。

所有学习方法应使用相同训练场景、参数预算说明和相同传统状态更新器，避免把状态滤波差异误认为关联网络差异。

## 15. 消融实验

建议至少包括：

1. 去除状态与量测协方差；
2. 去除 Doppler/速度残差；
3. 去除跨 BS 支持数量和可见性；
4. 欧氏距离门控替代马氏距离门控；
5. 边 MLP 替代二部图消息传递；
6. Hungarian 硬匹配替代 Sinkhorn 软匹配；
7. 去除身份对比损失；
8. 去除关联概率校准；
9. 不向第一图传递关联熵；
10. 使用 oracle association 替代预测关联。

第 9 项直接检验第二图是否真正延续了第一篇论文的不确定性主线；第 10 项用于量化数据关联错误对最终轨迹预测的影响上限。

## 16. 评价指标

### 16.1 检测与量测质量

- Precision、Recall、F1；
- 距离、Doppler、角度误差；
- 融合位置/速度 RMSE；
- 协方差 NLL、覆盖率和 ECE。

### 16.2 多目标跟踪与身份保持

- HOTA、DetA、AssA；
- IDF1；
- MOTA/AMOTA；
- ID Switch；
- Track Fragmentation；
- False Positive、False Negative；
- OSPA 或 GOSPA；
- 位置和速度 RMSE。

不能只报告边分类准确率，因为大量显然错误的负边会使该指标虚高。论文主指标应以 HOTA、IDF1、ID Switch 和 GOSPA 为主。

### 16.3 下游轨迹预测

- ADE/FDE；
- 交互目标 ADE/FDE；
- 低 SNR、轨迹交叉和遮挡子集 ADE/FDE；
- 预测关联与 oracle 关联之间的性能差距；
- ID Switch 前后预测误差变化。

### 16.4 通信指标

若论文保留 ISAC 通信闭环，可进一步报告：

- 多用户预测波束失配概率；
- 和速率；
- 波束切换或重捕获次数；
- 因 ID Switch 导致的用户波束错误分配率。

## 17. 性能闸门

建议设置以下阶段闸门，但不预设或伪造具体提升百分比：

1. 量测统计和协方差必须与设定噪声一致；
2. 简单场景中传统关联器必须正常工作；
3. 关联 GNN 的 IDF1、HOTA 和 ID Switch 至少同时优于 gated Hungarian-EKF；
4. 在交叉、遮挡和低 SNR 子集中，关联 GNN 应优于 JPDA-EKF 或说明失败条件；
5. 使用预测关联后，第一图 + LLM 仍应优于逐目标独立预测；
6. 加入关联熵后，应改善低 SNR/高歧义子集，而不是只改善总体平均值；
7. 报告与 oracle association 的差距，不能隐藏关联错误造成的性能损失。

若某一闸门未通过，应先定位是量测生成、门控、关联评分、生命周期还是状态更新的问题，再进入下一阶段。

## 18. 推荐的论文论证链

论文中建议依次回答五个问题：

1. **为什么需要第二图？** 已完成的交互图默认身份已知，无法处理回波叠加下的未知身份量测；
2. **第二图利用了什么额外信息？** 多 BS 几何、Doppler、状态协方差和邻域竞争；
3. **是否真正改善身份保持？** 用 HOTA、IDF1、ID Switch 和 GOSPA 证明；
4. **关联不确定性是否有价值？** 用概率校准和“去除关联熵”消融证明；
5. **是否改善最终任务？** 用 Graph+LLM 的 ADE/FDE 和预测辅助通信指标证明。

由此形成完整贡献：

> 第二图解决“当前量测属于谁”，第一图解决“多个目标如何相互影响”，不确定性运动 Token 与 LLM 解决“它们未来怎么运动”。

## 19. 风险与应对

### 风险 1：量测仿真过于理想

若量测直接由真值状态加独立高斯噪声得到，关联任务可能过于简单。应至少加入漏检、虚警、RCS 波动、BS 可见性和轨迹交叉。

### 风险 2：模型利用车辆 ID 泄漏

真实 ID 不得进入节点特征、边特征、排序规则或数据文件的模型输入字段；应随机打乱每帧量测顺序，并在测试时重新映射匿名 ID。

### 风险 3：虚警和负边导致类别失衡

使用物理门控、困难负样本挖掘和损失重加权，并报告每帧候选边数量。

### 风险 4：端到端训练不稳定

采用“量测验证 → 单帧关联 → 序列跟踪 → 接入预测 → 有限联合微调”的分阶段训练，不从第一天开始端到端训练全部模块。

### 风险 5：只提高 ADE/FDE，跟踪指标无改善

第二图的主要论点必须是身份保持和跟踪质量。若 HOTA/IDF1/ID Switch 没有改善，不能仅凭 ADE/FDE 宣称量测—航迹关联有效。

### 风险 6：工作量超出硕士阶段

主体论文先完成融合量测—航迹二部图，不把原始多 BS 量测异构图、复杂 MHT 和资源调度全部设为必选项。

## 20. 预计交付物

方案确认后，代码阶段应逐步形成：

1. 多 BS 多目标无身份量测数据集；
2. 三个传统关联/跟踪基线；
3. 不确定性感知量测—航迹关联图；

6. tracking、forecasting 和 communication 三类评估；

8. 对比、消融和典型关联场景的论文图。
